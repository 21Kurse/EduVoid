# TASKS.md

Ordered checklist for the loop. Tick a box only when its acceptance criteria are met **and** `npm run check` passes. After each task, commit and push to `origin/main`. Do tasks in order unless blocked. Tasks marked **[OWNER]** are never done by the agent. Spec: `AGENTS.md` (Section 13 overrides on conflict).

`npm run check` = typecheck + lint + unit tests + production build. Create it in T0 and never weaken it.

## Core

- [x] **T0 Scaffold and repo.** The GitHub repo https://github.com/21Kurse/EduVoid.git already exists (it may contain an initial commit and a Node `.gitignore` from GitHub). **Clone it and work inside the clone** (or `git pull origin main --allow-unrelated-histories`); never force-push. Scaffold Next.js (App Router) + TS, Tailwind, zod, vitest. Extend the existing `.gitignore` per AGENTS.md section 14 rather than overwriting it. Add `npm run check`, `.env.example`, `DECISIONS.md`, `PROGRESS.md`, `BLOCKERS.md`. Accept: check passes; home page renders; first commit pushed to `origin/main`; `.env.local` is ignored. Owner links the repo to Vercel.
- [x] **T1 Types and fixture.** zod schemas for `CurriculumSpec` (AGENTS.md section 4). Hand-write `fixtures/qm-superposition.json` (5-7 concepts, prerequisite edges, claims with passage IDs, explainers, quizzes, sim params). Accept: fixture validates; unit test asserts acyclic prerequisites and that every claim's passage IDs exist.
- [x] **T2 UI shell from fixture.** Single-question home -> loading -> learning view. Clean, minimal, light. React Flow mindmap with mastery-colored nodes; concept panel with explainer (KaTeX) and quiz component. Accept: fixture renders end to end; no console errors; works at laptop and phone widths.
- [x] **T3 LLM and search wrappers.** `lib/llm.ts` (role routing, zod-validated JSON, 2 retries with error feedback) and `lib/search.ts` (swappable provider), with mock providers for tests. Write `scripts/spike.ts`: (a) JSON validity rate on the real `CurriculumSpec` schema over 10 runs, (b) planted-error verifier test with 10 errors. Accept: unit tests pass with mocks.
- [ ] **GATE G1 (owner).** Owner supplies keys and the exact model ID, runs the spike, and decides role routing. Agent: stop and write `GATE_REACHED.md` until the owner clears it by deleting that file.
- [x] **T4 Source stage.** Search -> extractions via the provider's content API -> passages with stable IDs -> atomic claims; record contradictions. Accept: for the demo topic, returns >= 6 sources; every claim has passage IDs; results cached.
- [x] **T5 Plan stage.** Produce a valid `CurriculumSpec` skeleton (<= 8 concepts, acyclic prerequisites). Accept: schema validates; skeleton returned within ~15 s (log timing).
- [x] **T6 Generate stage.** One request per concept, streamed to the client; skeleton mindmap appears first, concepts fill in. Accept: per-stage timings logged; a failed concept shows a non-crashing error state with retry.
- [x] **T7 Verify stage.** Deterministic citation check plus LLM entailment verifier; drop or flag unsupported claims; "verified against N sources" badge; agent-activity panel. Accept: planted-error test meets the AGENTS.md amendment 4 threshold, or a stronger verifier model is configured and re-tested.
- [ ] **GATE G2 (owner).** Owner reads the generated demo-topic content for factual correctness and approves or lists fixes.
- [x] **T8 Cited claims UI.** Click a claim -> passage and source link; "sources disagree" display for contradictions. Accept: works for every claim; links open.
- [x] **T9 Predict-then-reveal sims.** Hand-built templates: two-state probability and double-slit interference; LLM supplies parameters and the prediction prompt; the sim stays locked until the user commits a prediction. Accept: prediction gating works; prediction vs outcome comparison shown.
- [x] **T10 Hero sim.** LLM-generated canvas/JS in `<iframe sandbox="allow-scripts" srcdoc>`, no network, `postMessage` only, render timeout, automatic fallback to a template. Accept: forced-failure test falls back cleanly.
- [x] **T11 Adaptive loop.** Deterministic mastery rules; failed concept regenerates in a different modality; visible one-line reason; mindmap colors update; state persists across reloads. Accept: unit tests for the rules plus a scripted scenario.
- [ ] **T12 Diagnostics.** 2-3 quick questions after topic entry set starting level and skip or unlock prerequisites. Accept: results change the plan input.
- [ ] **GATE G3 (owner).** Owner runs the full flow on the demo topic and reports problems.
- [ ] **T13 Test mode.** Loads `data/eval/questions.json` (external questions supplied by the owner; never generated by the app). Pre-test -> session -> post-test, per-participant timestamps in browser storage, CSV export. Kept separate from in-app quizzes. Accept: round trip with a sample file.
- [ ] **T14 Hardening.** Server-side keys only, per-IP rate limiting, topic safety check, error and empty states, demo-safe cached run clearly labeled "cached run". Accept: tests for rate limit and refusal; cached run never presented as live.
- [ ] **T15 Polish and docs.** README (problem, users, approach, architecture diagram in Mermaid, run instructions, honest limitations), complete `DECISIONS.md`, `.env.example`, final deploy checklist. **Feature freeze after this task.**
- [ ] **D1 Demo script.** Write `docs/DEMO.md`: timed video script and shot list per AGENTS.md 15.2, plus the list of 5 unseen topics to test live. Accept: narration is about 430 words or fewer (about 3:00 at 150 wpm); every beat maps to a feature that exists.
- [ ] **D2 Q&A prep.** Write `docs/QA.md` per AGENTS.md 15.4 using real numbers from `DECISIONS.md`, `PROGRESS.md`, spike and latency logs. Accept: all six questions answered; no invented metrics; Cut list in `DECISIONS.md` is complete.

- [ ] **D4 Unseen-input testing.** Run 5 topics not used in development (including one niche, one ambiguous, and one that should be refused). Log results in `PROGRESS.md`. Accept: no crashes; failures show a graceful state; fix what breaks.
